In Juju, a **placement directive** is an option based on the `--to` flag that can be passed to certain commands to specify a deploy location, where the commands include [`add-machine`](/t/1672) , [`add-unit`](/t/1679) , [`bootstrap`](/t/1688) , [`deploy`](/t/1707) , [`enable-ha`](/t/1718) and the location is  (1) an existing or a new machine ID or (2) a key-value pair specifying a subnet, system ID, or an availability zone. 

Example: `juju add-machine --to 1`, `juju deploy --to zone=us-east-1a`


The rest of this document gives details about the locations.

<!-- where the zone key may be used to override a `zones` [constraint](/t/6184).  -->

[note type=caution]
When the location is a key-value pair, its availability and meaning may vary from cloud to cloud. For details see [List of supported clouds > `<cloud name>`](/t/6665).
[/note]

<a href="#heading--machine"><h3 id="heading--machine">`<machine>`</h3></a>

The machine ID.

**Examples:** `1` (existing machine `1`), `lxd:5` (new container on machine 5), `5/lxd/0` (existing container `0` on machine `5`)

> See more: [Machine designations](/t/5459#heading--machine-designations)

<a href="#heading--system-id"><h3 id="heading--system-id">`system-id=<system ID>`</h3></a>

<!--**Value:** The system id.-->

Available for MAAS.

<a href="#heading--zone"><h3 id="heading--zone">`zone=<zone>`</h3></a>

<!--**Value:** The name of the availability zone.-->

**Purpose:** To specify an availability zone.

[note type=information]
The `zone` placement directive may be used to override a `zones` [constraint](/t/6184).
[/note]

**Example:** `zone=us-east-1a`
